### IRingBufferElasticBuilder&lt;T&gt;.Factory method
</br>


#### Sets the factory (required) to create an instance in the ring buffer asynchronously.

```csharp
public IRingBufferElasticBuilder Factory(Func<CancellationToken, Task<T>> value, 
    TimeSpan? timeout = default, byte maxConsecutiveFactoryFailures = 0)
```

| parameter | description |
| --- | --- |
| value | The handler to factory. |
| timeout | Per-item timeout for the factory call; also the deadline for the overall operation as `quantity * timeout` when creating several items at once (the initial warmup fill, or a scale-up) - so it bounds how long other engine operations wait behind it. Default is 15 seconds - inherited unchanged from a previous release, not calibrated against any particular factory. Set it deliberately based on how long your own factory call actually takes (e.g. opening a database connection or a broker channel), not the default. |
| maxConsecutiveFactoryFailures | How many consecutive factory failures (per-item timeout or exception) to tolerate within a single creation batch (the initial warmup fill, or a scale-up) before giving up on the remaining not-yet-attempted items. Resets to zero on every success, so only a true streak of failures counts, not isolated ones scattered across an otherwise healthy batch. Default is 0: the first failure gives up on the rest of the batch immediately (whatever succeeded before it is still kept) - the same behavior as before this parameter existed. Raise it if your factory has occasional, recoverable hiccups and you want the batch to keep trying the remaining items instead of abandoning them. If a tolerated failure is itself a *timeout* rather than a fast exception, raising this value multiplies *timeout*'s own worst-case blocking effect: the batch can now stay blocked for roughly `(maxConsecutiveFactoryFailures + 1) * timeout` before giving up on a given item, not just *timeout*. |
